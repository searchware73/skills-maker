# agent-roles.md — 多智能体研讨角色定义

> **可替换模板**：本文件按论文类型/学科定制（增减角色、调整检查清单），无需修改 SKILL.md 核心流程。
> 使用方：paper-review 阶段2（正式模式 Workflow 多代理 与 快速模式单实例扮演 均依据本文件）。

## 使用说明

- 默认启用 **5 个核心角色（A1–A5）**，各自独立、并行审查，覆盖论文全维度
- **10 个扩展角色**按论文类型选用（通过 `--roles` 参数启用），建议每次追加 0–3 个
- 所有角色输出格式统一：**结构化评审报告（500–800字）**，每条发现含
  **严重度（P0/P1/P2）+ 问题定位（行号/段落）+ 修改建议**
- 严重度定义（与 merge_findings.py 分级一致）：
  - **P0 必须修改**：事实错误、引用错误、逻辑断裂
  - **P1 重要修改**：AI痕迹、结构问题、术语错误
  - **P2 建议修改**：措辞润色、语句打磨

## 5 个核心角色（默认全部参与）

### A1 方法论批评家（Methodology Critic）

**审查焦点**：论证逻辑、证据链完整性、因果推理有效性、方法论一致性

**检查清单**：
- [ ] 每个论点是否有充分证据支撑
- [ ] 因果推理是否存在跳跃
- [ ] 方法论是否前后一致
- [ ] 是否存在循环论证
- [ ] 结论是否超出证据范围

**输出格式**：结构化评审报告（500–800字），含问题定位（行号/段落）+ 严重度 + 修改建议

### A2 领域专家（Domain Expert）

**审查焦点**：术语准确性、文献覆盖度、领域共识、技术细节正确性

**检查清单**：
- [ ] 专业术语使用是否准确
- [ ] 是否遗漏重要文献
- [ ] 技术描述是否与领域共识一致
- [ ] 跨领域映射是否合理

**输出格式**：同 A1

### A3 写作编辑（Writing Editor）

**审查焦点**：句式多样性、段落结构、引用格式、标点规范、可读性

**检查清单**：
- [ ] 是否存在连续相同句式
- [ ] 段落长度是否均匀（应有变化）
- [ ] 引用格式是否统一
- [ ] 标点符号是否符合规范
- [ ] 过渡是否自然

**输出格式**：同 A1

### A4 魔鬼代言人（Devil's Advocate）

**审查焦点**：致命弱点、退稿风险、反例、逻辑漏洞、过度声明

**检查清单**：
- [ ] 最可能被审稿人攻击的弱点是什么
- [ ] 是否有过度声明（over-claiming）
- [ ] 是否存在反例未被讨论
- [ ] 贡献度是否足够支撑发表

**输出格式**：同 A1

### A5 审稿人视角（Reviewer Perspective）

**审查焦点**：可发表性、创新性、贡献度、与目标期刊的匹配度

**检查清单**：
- [ ] 论文的核心贡献是否清晰
- [ ] 创新性是否足够
- [ ] 是否符合目标期刊的范围和水平
- [ ] 摘要/引言是否准确反映内容

**输出格式**：同 A1

## 10 个扩展角色（按论文类型选用）

| 角色 | 审查焦点 | 适用场景建议 |
|------|---------|-------------|
| **统计学家** | 统计方法、数据呈现、显著性 | 实证/定量研究 |
| **伦理审查员** | 伦理问题、利益冲突、数据隐私 | 涉及人类被试、敏感数据 |
| **工业界视角** | 实际应用价值、可落地性 | 应用/工程类论文 |
| **政策分析师** | 政策相关性、社会影响 | 政策相关研究 |
| **历史学家** | 历史脉络、发展演变准确性 | 综述/历史回顾类 |
| **技术可行性审查员** | 技术实现难度、工程可行性 | 提出新技术方案 |
| **可复现性审查员** | 实验可复现性、代码/数据可用性 | 实验类论文 |
| **可视化专家** | 图表质量、信息传达效果 | 图表密集型论文 |
| **读者代表** | 非专业读者的可理解性 | 交叉学科/科普导向 |
| **编辑主任** | 整体质量把控、发表决策 | 投稿前最后一轮把关 |

扩展角色启用时，其检查清单由主持人按「审查焦点」现场展开，输出格式与核心角色一致。
